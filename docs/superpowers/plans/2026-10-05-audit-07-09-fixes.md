`docs/audit/09-outputs-sets-ledger-review.md` (read each "Verification, 2026-10-05" section), and
`docs/audit/next-session-prompt.md` for the group table and the owner decisions.

## Review Focus

Inputs no current test exercises that are most likely to bite, each with its test in the owning task or group:

1. A Setup toggle whose save fails: the Setup page must show the setting still on disk, not the one clicked
   (Task 1, `test_a_failed_toggle_leaves_this_pcs_config_alone`).
2. A Setup toggle after another PC's change: this PC's in-memory config must hold that change afterwards too, so
   the next save from any other path keeps it (Task 1, `test_a_setup_toggle_refreshes_this_pcs_config`).
3. A migration whose save failed: the next load, once the file is free, must still persist the migration
   (Task 4, `test_a_failed_migration_save_is_retried_on_the_next_load`).
4. Reopening a session after a re-run: the stale undo stack must not come back from `operations_history.json`
   (Task 3, `test_a_rerun_empties_the_saved_undo_history`).
5. Closing the app while the group E background queue holds unwritten work: it must flush before exit (group E).

## Group A: data safety (07-H1, 07-M6, 08-U1, 07-M7)

One PR. Small, and it stops config loss and undo duplication.

**Risk:** low. After a toggle this PC's config also picks up every other change on disk (rules, sets): intended,
that is the fix. A migration that cannot save is retried on each load until it saves. Undo history is emptied by
every successful run, so edits made before a re-run can no longer be undone (they belong to a frame that no longer
exists).

## Group C: atomic and honest saves (07-M2, 07-M3, 07-M4, 09-O5)

**Tests:** `test_AUDIT_07_M2_the_run_writes_its_state_files_atomically`,
`test_AUDIT_07_M3_a_failed_state_save_is_reported`, `test_AUDIT_07_M4_a_write_outlasts_a_one_second_read`
(three writers), `test_AUDIT_09_O5_the_packing_list_json_is_written_atomically`,
`test_AUDIT_09_O5_a_failed_packing_build_does_not_empty_the_session`.

**Files:** `shopify_tool/core.py` (`_save_results_and_reports`, `_create_analysis_data_for_packing`),
`shopify_tool/session_state.py`, `shopify_tool/fulfillment_history.py`, `shared/atomic_write.py`,
`gui/actions_handler.py` (packing-list JSON, `on_analysis_complete` toast).

**Approach:** the run writes `current_state.pkl` through `session_state.save_state` and both JSON files through
`atomic_write_json`. One retry helper with exponential backoff, a few seconds in total, for `PermissionError`
only, used by all three writers. A failed state save surfaces as a `*_warning` stat that
`on_analysis_complete` toasts like `history_warning` (the M3 test accepts that or a failed run; pick one in that
session and say which in the PR). A failed packing build raises instead of saving an empty session.

**Risk:** medium. `shared/` changes reach packing-tool at its next sync: say so in the PR. A longer retry makes a
genuinely locked file take seconds to report.

moves to a `Worker` and reports back by signal.

**Risk:** medium-high. Vectorising can change edge behaviour (NaN, mixed types, order of added rows). Run the
existing suites first and keep them unchanged.
