# Analysis Results 1b — the chrome (Phase 8.8b) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle the Analysis Results screen to the Phase 8 design system — a KPI strip, a 3px status edge instead of a filled row tint, `ContextualSelectionBar` instead of `BulkOperationsToolbar`, and `FilterBar` instead of the hand-rolled filter row — while restoring the repeat-order signal that 8.8a silently dropped.

**Architecture:** Presentation only. `analysis_results_df` stays the source of truth and no file under `shopify_tool/` is touched. The model stops emitting `QColor` and starts emitting a theme *role token name* on a private item role; a new delegate resolves that token against the live theme and paints a left edge. The three container widgets this screen adopts (`KpiStrip`, `FilterBar`, `ContextualSelectionBar`) already exist in `gui/components/` and are already used elsewhere in the app — this cycle writes exactly one new widget, the edge delegate.

**Tech Stack:** Python 3, PySide6 (Qt Widgets), pandas, pytest (`QT_QPA_PLATFORM=offscreen`), ruff.

**Spec:** `docs/superpowers/specs/2026-08-30-phase8.8b-analysis-results-chrome-design.md`

Parent spec (read §8 and §9 for why this cycle exists at all): `docs/superpowers/specs/2026-08-30-analysis-results-1b-design.md`

## Global Constraints

- **Never hand-edit anything under `shared/`.** It is one-way synced from `../packing-tool`. Nothing in this plan needs to change it — if you believe it does, stop and say so.
- **No hardcoded colours.** Every colour comes from `get_theme_manager().get_current_theme()`. No `#666`, no `color: gray`.
- **No direct commits to `main`.** This work is on the branch `worktree-phase8-results-1b-chrome`; the PR is Stage C's job, not yours.
- **Dark is designed, light is derived.** Build to the dark mockup; let light fall out of the tokens. Do not claim design parity in both themes.
- **Attribute names on `MainWindow` are load-bearing.** `filter_input`, `settings_button_tab2`, `configure_columns_button_tab2`, `add_product_button_tab2`, `undo_button`, `theme_toggle_btn`, `generate_reports_button_tab2` are read from `main_window_pyside.py`, `actions_handler.py` and the test suite. - **No version bump.** This is a UI cycle inside pre-release 1.9.9.1; the three-file version rule in `CLAUDE.md` applies to releases, and 8.8a did not bump either.
- **The full suite takes ~18 minutes on this VM.** Budget for it. A 10-minute tool timeout will kill it mid-run. Run single test files during the task loop and the full suite only at the end.

```python
    def _build_row_status_cache(self):
        """Pre-compute each row's status token: "status_warning" / "_success"
        / "_danger", or None.

        Token names, not colours, so the cache survives a theme change --
        StatusEdgeDelegate resolves them against the live theme at paint time.

        Serves both tables this model backs. The order frame answers "is this a
        repeat?" from the derived `_repeat` column (System_note is line-level
        and does not survive the fold); the detail pane's lines table has
        System_note itself and no Order_Fulfillment_Status. Presence checks,
        not two code paths.

        Assumption unchanged from the colour cache it replaces: the DataFrame
        is immutable after the model is created. Mutate rows in place and you
        must call this again.
        """
        n = len(self._dataframe)
        columns = self._dataframe.columns

        repeat_col = columns.get_loc(REPEAT_COLUMN) if REPEAT_COLUMN in columns else -1
        note_col = columns.get_loc("System_note") if "System_note" in columns else -1
        status_col = (
            columns.get_loc("Order_Fulfillment_Status")
            if "Order_Fulfillment_Status" in columns
            else -1
        )

        cache = [None] * n
        for i in range(n):
            try:
                if repeat_col >= 0 and bool(self._dataframe.iat[i, repeat_col]):
                    cache[i] = "status_warning"
                    continue
                if note_col >= 0 and is_repeat(self._dataframe.iat[i, note_col]):
                    cache[i] = "status_warning"
                    continue
                if status_col >= 0:
                    status = self._dataframe.iat[i, status_col]
                    if status == "Fulfillable":
                        cache[i] = "status_success"
                    elif status == "Not Fulfillable":
                        cache[i] = "status_danger"
            except (IndexError, KeyError):
                pass

        self._row_status_cache = cache
```

```python
"""Paints a row's status as a left edge, never as a filled row.

Parcker's rule: status is an edge, a chip or a tint, never a filled row -- a
filled row cannot show *selected* and *blocked* at the same time, and the
selection ring shipped in 8.7 needs the row background to stay neutral.

The base item is drawn first, through the widget's own style, so the
stylesheet's selection ring (shared/theme.py -- selection_bg plus a 2px
selection_border top and bottom) still renders underneath the edge.

Spec: docs/superpowers/specs/2026-08-30-phase8.8b-analysis-results-chrome-design.md
"""

from PySide6.QtGui import QColor
from PySide6.QtWidgets import QApplication, QStyle, QStyledItemDelegate, QStyleOptionViewItem

from gui.pandas_model import ROLE_STATUS
from gui.theme_manager import get_theme_manager

EDGE_WIDTH = 3


class StatusEdgeDelegate(QStyledItemDelegate):
    """A 3px bar in the row's status colour, on the leftmost visible column."""

    def edge_token(self, index) -> str | None:
        """The row's theme role token, or None. Pure: no painting, no theme."""
        return index.data(ROLE_STATUS)

    def paints_edge(self, header, column: int) -> bool:
        """True for the column the user currently sees on the left.

        Visual index, not logical: a user who drags a column to the front must
        still get the edge on the left of the row.
        """
        return header is not None and header.visualIndex(column) == 0

    def paint(self, painter, option, index):
        opt = QStyleOptionViewItem(option)
        self.initStyleOption(opt, index)
        style = opt.widget.style() if opt.widget else QApplication.style()
        style.drawControl(QStyle.CE_ItemViewItem, opt, painter, opt.widget)

        token = self.edge_token(index)
        if not token:
            return
        widget = opt.widget
        header = widget.horizontalHeader() if hasattr(widget, "horizontalHeader") else None
        if not self.paints_edge(header, index.column()):
            return

        theme = get_theme_manager().get_current_theme()
        edge = option.rect
        edge.setWidth(EDGE_WIDTH)

        painter.save()
        painter.fillRect(edge, QColor(getattr(theme, token)))
        painter.restore()
```

```python
        """Orders, fulfillable, blocked, items -- from the line frame.
```
