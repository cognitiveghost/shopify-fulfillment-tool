# Phase 8.6 Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to
> implement this plan task-by-task. (The roadmap runner's Stage B declines the
> subagent-driven variant and stays in-session.) Steps use checkbox (`- [ ]`) syntax.

**Goal:** Replace the Shopify Tool's tab bar with `NavRail` and its two-row global header
with `CommandBar`, without changing a single destination label.

**Architecture:** `main_tabs` stays a `QTabWidget` with its tab bar hidden — it remains the
page store, so its 30 call sites and the five `Ctrl+N` shortcuts are untouched. `NavRail`
becomes the chrome and binds to it two-way. `CommandBar` takes over the header row; the
client dropdown becomes the selector while `ClientSidebar` keeps client *management* and
starts collapsed.

**Tech Stack:** PySide6, pytest with `QT_QPA_PLATFORM=offscreen`, ruff.

**Spec:** `docs/superpowers/specs/2026-08-27-phase8.6-shell-design.md`

## Global Constraints

- **Two commits, in this order, never squashed:** (1) chrome — CommandBar in, header out,
  sidebar collapsed; (2) navigation — NavRail in, tab bar hidden. Navigation must be
  revertible on its own (spec §6 guardrail 1).
- **Destination labels are verbatim:** `Session Setup`, `Analysis Results`,
  `Session Browser`, `Information`, `Tools`. No renames this release (guardrail 2).
- **Never hand-edit `shared/`** — it is synced from `../packing-tool`. This plan does not
  touch it.
- **No hardcoded colours or sizes.** Use `theme.*` tokens and `font_css(...)`;
  `shared/style_lint.py` enforces it and `tests/test_style_literals.py` will fail.
- **Do not flip the global button default to neutral.** Button roles stay opt-in per
  8.5's recorded decision.
- Gate before finishing: `QT_QPA_PLATFORM=offscreen .venv/bin/python -m pytest` and
  `.venv/bin/ruff check . --exclude shared`. Run `./scripts/setup_venv.sh` first in a
  fresh worktree.

### Task 1: `CommandBar.add_tool_button()`

The bar ships with one trailing widget, the primary `action_button`. The header hands it
two more (connection settings, sidebar toggle), and 8.7 will hand it more. They are ghost
role: "one primary per screen" must stay structurally true.

**Files:**
- Modify: `gui/components/commandbar.py`
- Test: `tests/test_components_commandbar.py`

**Interfaces:**
- Consumes: `set_button_role` from `gui.theme_manager` (already imported there);
  `icon(name)` from `gui.icons`.
- Produces: `CommandBar.add_tool_button(icon_name: str, tooltip: str) -> QPushButton`.
  Buttons appear left of the stretch, in call order. `CommandBar.action_button` remains
  the only widget on the bar with the `primary` role.

**Why `QPushButton` and not `QToolButton`:** the role rules in `shared/theme.py:554-594`
are all `QPushButton[role="..."]`. A `QToolButton` matches none of them and would come out
unstyled. The header's two buttons are `QPushButton`s today, so this also keeps
`_BUTTON_ICONS`' `setIcon` call working unchanged.

```python
    def add_tool_button(self, icon_name: str, tooltip: str) -> QPushButton:
        """Append a ghost tool button left of the primary action.

        Ghost, never primary: the bar's one primary is action_button, and
        that is what makes "one primary per screen" structural rather than a
        convention a call site can break.

        A QPushButton, not a QToolButton: every role rule in shared/theme.py
        is a QPushButton[role="..."] selector, so a QToolButton here would be
        the one unstyled control on the bar.
        """
        button = QPushButton(self)
        button.setIcon(icon(icon_name))          # raises KeyError on a typo
        button.setToolTip(tooltip)
        button.setFlat(True)
        set_button_role(button, "ghost")
        self.layout().insertWidget(self._tool_slot, button)
        self._tool_slot += 1
        return button
```
