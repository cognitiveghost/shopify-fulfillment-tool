# Phase 8.7 / 1e — Session Browser

Applies the Phase 8 unified design system to `gui/session_browser_widget.py`.
Parent: `docs/superpowers/specs/2026-08-26-phase8-unified-design-system.md` (§4 status
semantics, §5 component inventory, §6 screens). Depends on 8.5 (components) and 8.6 (shell),
both merged — `main` @ `900e9cb`.

Two user decisions taken 2026-08-28 are recorded in §4 and §5 and are the design, not
options.

---

## 1. What is actually wrong, measured

The roadmap brief lists three defects. One of them is already fixed:

| brief says | true on `900e9cb`? |
|---|---|
| status column has hardcoded `color: blue/darkgreen/red` | **No — fixed by 8.3.** `session_browser_widget.py:441-451` already reads `theme.status_info` / `status_success` / `status_danger` / `text_secondary`. |
| comments column is a per-row `QLineEdit`, 0 of 42 real sessions use it | Yes — `:488-496` |
| `ColumnConfigPanel` list collapse | Yes, but **not on this screen** — see §8 |

So the remaining defect in the status column is the **widget**, not the colour. A
`WheelIgnoreComboBox` in every row is what makes the row eight controls instead of one
object, and it is the direct cause of the hover hack at `:635-648`: interactive cell widgets
forward mouse-move, so Qt repaints the selection under the cursor, so a `viewport()`
event filter has to swallow every button-less `MouseMove`. Delete the cell widgets and that
whole apparatus stops being necessary.

**The unit of this screen is the session.** Today it is the cell.

---

## 2. Row anatomy

Seven columns, every one a plain `QTableWidgetItem`. No `setCellWidget` anywhere.

| # | column | content | sorts on |
|---|---|---|---|
| 0 | Session Name | name; `DecorationRole` carries a comment marker when a comment exists | text |
| 1 | Created | `%Y-%m-%d %H:%M` | text (ISO-ordered, so lexical = chronological) |
| 2 | Status | painted by `SessionStatusDelegate` (§3) | status text |
| 3 | Orders | count or `N/A` | text |
| 4 | Items | count or `N/A` | text |
| 5 | Packing Lists | count | text |
| 6 | Packing | `packed/total` painted as a bar by `PackingProgressDelegate` | `_RatioSortItem`'s `UserRole` ratio (unchanged) |

Column 7 (Comments) is removed — §5.

Row height comes from `get_density_profile().row_height` (28 desk / 40 floor), not a
literal. Default sort stays Created descending.

The full-detail tooltip stays and now covers **every** cell in the row: today
`:509-513` skips columns 2 and 7 because `item(row, col)` returns `None` for a cell holding
a widget, so hovering the status or comment cell shows nothing.

## 3. Status: dot or chip, and which one is the contract

Parent spec §4: *"Colour carries urgency, tint carries authorship. A plain dot means a
person put the session in this state. A tinted chip means the system detected it."*

Authorship is **real per-row data here, not a property of the state**.
`session_manager.update_session_status(..., manual=True)` writes `status_manually_set`
(`session_manager.py:467-468`), and `session_lifecycle.py:110` reads it to decide whether to
leave the session alone. So the rule renders literally:

- `session_info["status_manually_set"]` truthy → **dot form**: a filled circle in the role
  colour, label text in `theme.text`.
- otherwise (derived by `derive_status_updates`) → **chip form**: a rounded pill filled with
  the role's `_bg` tint, label text in the role colour.

Role mapping for the four Shopify session states:

| status | role | notes |
|---|---|---|
| `active` | `status_info` | |
| `completed` | `status_success` | auto-completed sessions render as tinted chips |
| `abandoned` | `status_danger` | |
| `archived` | `text_secondary` | **amends parent §4's table**, which had no `archived` key — the parent's own rule is that a state with no equivalent gets a key there first |

`text_secondary` has no `text_secondary_bg` partner; `StatusChip` already documents this
exact case and falls back to `surface_sunken`, so an auto-archived row reads as a grey pill.
The delegate uses the same fallback.

**Divergence guard.** The delegate resolves its two colours with the same two lines
`StatusChip.set_status` uses — `getattr(theme, role)` and
`getattr(theme, f"{role}_bg", theme.surface_sunken)`. It does not import or render a
`StatusChip`: a `QLabel` in a cell is a cell widget, which is the thing being removed.
A test asserts the delegate's resolved pair equals `StatusChip`'s for every status key in
both themes, so the duplication fails the build if it ever drifts.

> Deliberately **not** hoisting a shared `chip_colors()` helper into `shared/theme.py`. That
> is a cross-repo edit (author in `packing-tool`, then `scripts/sync_shared.py`) for two
> lines, and it drags a second repo into a single-screen cycle. When 8.9 gives packing-tool
> its own painted status column, that is the second call site and the moment to hoist.

## 4. Changing a status — the selection bar

*(User decision, 2026-08-28: "Selection bar Status ▾".)*

The inline combobox is gone, so the read-only chip needs somewhere for the edit to live.
`ContextualSelectionBar` (shipped in 8.5, currently zero call sites — this is the one it was
built for) appears whenever ≥1 row is selected and carries:

| action | enabled | role |
|---|---|---|
| `Status ▾` — Active / Completed / Abandoned / Archived | ≥1 row | secondary |
| `Comment…` | exactly 1 row | secondary |
| `Export Combined Stock` | ≥2 rows | secondary |
| `Open` | exactly 1 row | primary |

`Status ▾` is a `QPushButton` with a `QMenu` (`ContextualSelectionBar.add_action` returns the
button, so `setMenu` needs no new API). It applies to **every selected row**, each write
going through the existing `_on_status_changed(session_path, new_status)` unchanged —
`manual=True`, one `update_session_status` call per row, then one refresh. Bulk archiving of
old sessions is the capability the per-row combobox never had.

The bar replaces the two-button footer row at `:236-253`. `Open Selected Session` and
`Export Combined Stock` stop being permanently visible controls that are disabled most of
the time.

The signals `session_selected` and `multi_export_requested` keep their names and payloads,
so `main_window_pyside.py:304-305` and `actions_handler.py` are untouched. Blast radius stays
inside this widget.

**Opening a session is unchanged**: double-click, or Enter, or the bar's `Open`. "The whole
row is the hit target" (parent §6) means the row is one object rather than eight controls —
it does **not** mean single-click opens. Single-click-to-open would fight multi-select, and
it is exactly the kind of muscle-memory change the navigation guardrails exist to avoid.

## 5. Comments — off the grid, not deleted

*(User decision, 2026-08-28: "Rethink: move it off the grid".)*

0 of 42 real sessions carry a comment, but the affordance was an unlabelled `QLineEdit` in
the eighth column of a horizontally-scrolling table — weak evidence that the feature is
unwanted. It moves rather than dies:

- **Visible**: when `session_info["comments"]` is non-empty, the name cell's
  `DecorationRole` shows a `message-square` glyph. `DisplayRole` is untouched, so sorting and
  every existing test that reads session names by text stay correct.
- **Readable**: the comment text is already in the row tooltip (`:507`) and stays there.
- **Editable**: the selection bar's `Comment…` opens a `QInputDialog.getMultiLineText`
  seeded with the current text; accepting calls the existing
  `_on_comments_changed(session_path, text)` unchanged.

`message-square.svg` is not in `gui/assets/icons/` and must be added (Lucide, MIT, same
vendoring as the other 17 glyphs). `icon()` raises `KeyError` on a missing name, so a
forgotten file fails at construction, not invisibly at paint.

## 6. Filter row

The `QGroupBox("Existing Sessions")` wrapper is deleted. Regions separate by elevation and
space (parent, fault #1); the NavRail destination already names the screen, so the group box
is a border drawing a label that is on screen twice.

One row above the table:

```
[ FilterBar: search field ......................  12 sessions ]  [ Status ▾ ] [ Refresh ] [ Show Archived ]
```

- **`FilterBar`** (8.5, currently zero call sites) supplies the search field and the count.
  Search filters `self.sessions_data` **client-side** on session name — no file-server round
  trip. The count reads `N sessions` / `N of M sessions` when a search or the archived filter
  is narrowing the list.
- **Status** stays a `WheelIgnoreComboBox`. It is a *server-side query* — `_apply_filter`
  triggers a real `refresh_sessions()` — so it is not the same kind of control as the search
  box and does not belong inside it.
- **Refresh** and **Show Archived** keep their current behaviour verbatim.

> Skipped: `FilterBar`'s removable filter chips. With one filter dimension, a chip reading
> `Status: Active` next to a combobox already reading `Active` is the same state drawn twice.
> Add chips when a second dimension (date range, worker) appears.

## 7. What gets deleted

- `QGroupBox` wrapper (`:161-162`, `:255`)
- per-row `WheelIgnoreComboBox` status widget (`:435-457`)
- per-row `QLineEdit` comments widget and column 7 (`:488-496`, `:206`, `:231`)
- the footer button row (`:236-253`)
- `eventFilter` and its `viewport()` install (`:257-261`, `:635-648`) — it exists solely
  because interactive cell widgets forward hover events. With no cell widgets, a plain
  `QTableWidget` does not move the selection on hover. **A test proves this** rather than the
  removal being argued from the comment.

`_on_status_changed`, `_on_comments_changed`, `refresh_sessions`, `_do_refresh_sync`,
`set_client`, `mark_dirty`, `showEvent`, `closeEvent`, `SessionLoaderWorker` and the
automatic status sync are all untouched. This is a presentation change; the data path stays
where 2026-08-24's overhaul put it.

## 8. Non-goals

- **`ColumnConfigPanel`'s list collapse.** The roadmap files it under 1e, but
  `column_config_dialog.py:122` is instantiated only by `gui/settings/window.py:394` and
  `column_config_dialog.py:1041` — the Settings window and its dialog. It is not on the
  Session Browser screen and shares no code with it. Bundling two screens into one PR makes
  the navigation half un-revertable independently, which the guardrails forbid. It should be
  its own small item; the fix is the 2026-08-23 scroll-area starvation pattern applied to
  `self.column_list`.
- **Model/view rewrite.** `QTableWidget` + `setSortingEnabled` + `_RatioSortItem` works and
  is tested. A `QAbstractTableModel` buys nothing at 42 rows and turns a presentation change
  into a data-layer change.
- **packing-tool's session list.** That is 8.9, and it needs the shared-hoist discussed in
  §3.
- **Light theme parity.** Per 8.8's rule, recorded here so 1e follows it: build to the dark
  mockup, derive light from the tokens, and say so in the PR. Contrast is safe in both (every
  token is validated), but light is an implementer's reading until it gets its own pass.

## 9. Acceptance tests

The spec is only real where a test asserts it.

1. **No cell widgets.** `sessions_table.cellWidget(r, c) is None` for every cell of a
   populated table.
2. **Chip colours do not drift.** For each of the four statuses, in both themes, the
   delegate's resolved `(fg, tint)` equals what `StatusChip` resolves for the same role.
3. **Authorship picks the form.** A session with `status_manually_set` renders the dot form;
   one without renders the tinted chip form.
4. **Archived resolves.** `archived` maps to `text_secondary` and falls back to
   `surface_sunken` for its tint without raising.
5. **Comment marker.** Non-empty `comments` → the name item has a non-null icon and the
   tooltip contains the text; empty → null icon.
6. **Comment round-trip.** The bar's `Comment…` path calls `_on_comments_changed` with the
   dialog's text.
7. **Bulk status.** With three rows selected, `Status ▾ → Archived` calls
   `update_session_status` three times, each with `manual=True`.
8. **Selection bar visibility.** Hidden with nothing selected; `Open` enabled at exactly one
   row; `Export Combined Stock` enabled at two or more.
9. **Hover does not move the selection** — a synthetic button-less `QMouseEvent` over row 3
   leaves `currentRow()` where it was, with the event filter gone.
10. **Search is client-side.** Typing in the search field changes the visible row count
    without calling `session_manager.list_client_sessions`.
11. **Row height follows density.** `verticalHeader().defaultSectionSize()` equals
    `get_density_profile().row_height` under both profiles.
12. **The three existing test modules stay green unmodified** —
    `test_session_browser_columns.py`, `test_session_browser_lifecycle_sync.py`,
    `test_session_browser_reload.py`. The Packing column keeps `packed/total` as its
    `DisplayRole` text (the bar is painted *behind* it), which is what keeps
    `test_shows_packed_over_total` true.
