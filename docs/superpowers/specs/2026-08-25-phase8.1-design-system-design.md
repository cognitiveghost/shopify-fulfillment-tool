## 1. What the audit actually found

The scope doc's token survey was written from a read of the dataclass field list. Measuring
the values changed the picture in three ways worth recording, because they redirect 8.2.

**Correction — spacing and radius scales already exist.** `shared/theme.py` defines
`spacing_xs/sm/md/lg/xl` (4/8/12/16/24) and `radius: int = 4`. The scope doc's claim of "no
spacing or radius scale" is wrong for spacing and half-wrong for radius (one value, no
scale). 8.2 is therefore smaller than scoped on this axis.

**The accent colours have no per-theme values at all.** `accent_blue/green/orange/red` are
dataclass *defaults*. Neither `LIGHT_THEME` nor `DARK_THEME` overrides them, so both themes
render identical status colours on opposite backgrounds. Measured against each theme's
background:

| token | value | on light | on dark |
|---|---|---|---|
| `accent_blue` | `#007ACC` | 4.51:1 | 4.66:1 |
| `accent_green` | `#4CAF50` | **2.78:1** | 7.56:1 |
| `accent_orange` | `#FF9800` | **2.16:1** | 9.74:1 |
| `accent_red` | `#F44336` | **3.68:1** | 5.70:1 |

Light mode fails WCAG AA (4.5:1) on three of four status colours, orange by a factor of two.
The palette was tuned on dark and light inherited it. **This is the highest-value fix in
Phase 8** — it is a correctness bug in a warehouse app where orange means "check this",
not a matter of taste.

**Borders are binary: maximum or invisible.** `border` is `#1A1A1A` on light and `#FFFFFF`
on dark — 17.4:1 and 21.0:1, i.e. pure text contrast used for every box outline, which is
what makes both apps look harsh. `border_subtle` is 1.61:1 / 2.03:1, below the 3:1 non-text
minimum, i.e. invisible. There is no usable middle value, so every widget picks one extreme.

**Elevation does not exist in practice.** `background_elevated` differs from `background` by
1.04:1 (light) and 1.10:1 (dark). A dialog over a card over the window is three
indistinguishable planes.

`text_disabled` is also below 3:1 in both themes (2.32 / 2.16).

## 2. The hard constraint: additive only

`ThemeTokens`' docstring records that field names are deliberately frozen — roughly 180 call
sites across `gui/*.py` and `src/*.py` read them by exact attribute name. **8.2 adds fields
with defaults and re-values the existing ones. It renames nothing and deletes nothing.**

That single rule is what keeps 8.2 a one-file change instead of a 180-site refactor, and it
is why the tables below keep `accent_*` alive as aliases rather than replacing them.

Ownership is unchanged and non-negotiable: every edit lands in `packing-tool`'s
`shared/theme.py` first, then `python scripts/sync_shared.py` from this repo. Never the
reverse.

## 3. Colour tokens

All values below were generated by walking lightness in HLS with **hue held fixed** — this
is the "retune, not rebrand" the user chose in Q1 — and then verified against the WCAG 2.1
relative-luminance formula. No value in this section is an estimate.

### 3.1 Surfaces — a real three-step elevation scale

| token | light | dark | use |
|---|---|---|---|
| `surface` | `#FFFFFF` | `#0A0A0A` | window background |
| `surface_raised` | `#F4F4F5` | `#17171A` | cards, panels, table headers |
| `surface_overlay` | `#EAEAEC` | `#232327` | dialogs, popovers, menus |

Dark's base moves `#000000` → `#0A0A0A`. Pure black gives elevation nowhere to go — every
raised plane can only get lighter, and against `#000000` the first step reads as a smudge.
`background` / `background_elevated` stay as aliases of `surface` / `surface_raised`.

### 3.2 Text

| token | light | ratio | dark | ratio | target |
|---|---|---|---|---|---|
| `text` | `#1A1A1A` | 17.40:1 | `#F2F2F2` | 17.68:1 | ≥7 (AAA) |
| `text_secondary` | `#5A5A5A` | 6.90:1 | `#B0B0B0` | 9.13:1 | ≥4.5 |
| `text_disabled` | `#949494` | 3.03:1 | `#6E6E6E` | 3.88:1 | ≥3 |
| `text_placeholder` | `#767676` | 4.54:1 | `#8A8A8A` | 5.73:1 | ≥4.5 |

Dark `text` moves `#FFFFFF` → `#F2F2F2`: pure white on near-black is the classic halation
pair, and these screens are read for a full shift.

`text_disabled` is raised to a 3:1 floor. WCAG exempts disabled controls; a warehouse floor
does not, and a disabled-looking control the operator cannot read is a support call.

### 3.3 Borders — the missing middle

| token | light | ratio | dark | ratio | use |
|---|---|---|---|---|---|
| `border` | `#8A8A8A` | 3.45:1 | `#6B6B6B` | 3.72:1 | functional outlines: inputs, table grid, card edges |
| `border_subtle` | `#D8D8D8` | 1.43:1 | `#2E2E2E` | 1.46:1 | decorative dividers only |
| `border_strong` | `#1A1A1A` | 17.40:1 | `#F2F2F2` | 17.68:1 | today's `border`, kept for deliberate emphasis |

`border` drops from 17.4:1 to 3.45:1 — comfortably over the 3:1 non-text minimum and no
longer competing with text. `border_strong` preserves the old value so any site that
genuinely wanted maximum contrast keeps it explicitly rather than by default.

### 3.4 Status roles

Roles, not raw hues. Each foreground clears **4.5:1 against both the page surface and its
own tint**, so a badge is readable whether or not it sits on its tinted background.

**Light**

| role | fg | on surface | tint | fg on tint |
|---|---|---|---|---|
| `status_info` | `#006FBA` | 5.27:1 | `#E3F2FD` | 4.62:1 |
| `status_success` | `#367D39` | 5.06:1 | `#EAF6EA` | 4.55:1 |
| `status_warning` | `#A16000` | 5.01:1 | `#FDF2E3` | 4.53:1 |
| `status_danger` | `#D0190B` | 5.49:1 | `#FDE4E3` | 4.54:1 |

**Dark**

| role | fg | on surface | tint | fg on tint |
|---|---|---|---|---|
| `status_info` | `#0089E6` | 5.39:1 | `#042134` | 4.50:1 |
| `status_success` | `#4CAF50` | 7.12:1 | `#112712` | 5.71:1 |
| `status_warning` | `#FF9800` | 9.19:1 | `#342104` | 7.14:1 |
| `status_danger` | `#F44336` | 5.38:1 | `#340704` | 4.84:1 |

Tint tokens are `status_<role>_bg`. Dark keeps three of four original hues unchanged — dark
was already correct; it is light that is being repaired.

`accent_blue/green/orange/red` remain as aliases of `status_info/success/warning/danger` so
existing call sites keep working and silently improve. 8.3 migrates them to the role names.

### 3.5 Selection, and the token that means two things

`active_border` is currently `#4CAF50` — the same green as success. Selection and success
are unrelated meanings sharing one value, so neither can be retuned without corrupting the
other. They split:

| token | light | dark | use |
|---|---|---|---|
| `selection_border` | `#006FBA` | `#0089E6` | selected row/tab/card outline |
| `selection_bg` | `#E3F2FD` | `#042134` | selected row fill |
| `focus_ring` | `#0064AB` (6.16:1) | `#4DA9E8` (7.69:1) | keyboard focus — **new** |

Selection moves from green to the info hue. Green now means success and only success.

`focus_ring` is new and is not cosmetic: several stylesheets override Qt's default focus
indicator, leaving keyboard navigation with no visible focus at all. Both values clear the
3:1 non-text minimum.

`active_background` / `active_border` stay as aliases of `selection_bg` / `selection_border`.

## 4. Non-colour scales

**Spacing** — existing `xs/sm/md/lg/xl` (4/8/12/16/24) is kept unchanged. Adds
`spacing_2xl = 32` for page-level gutters, the one gap the audit found.

**Radius** — `radius = 4` is kept as-is. Adds a scale:

| token | value | use |
|---|---|---|
| `radius_sm` | 3 | inputs, badges, chips |
| `radius_md` | 6 | buttons, cards |
| `radius_lg` | 10 | dialogs, popovers |

**Type** — no typographic scale exists today; sizes are hardcoded per widget, and that
accounts for a meaningful share of the 125 hardcoded-value hits 8.3 has to clear.

| token | px | weight | use |
|---|---|---|---|
| `font_size_display` | 20 | 600 | screen titles |
| `font_size_heading` | 16 | 600 | section headers |
| `font_size_subheading` | 14 | 600 | card titles, table headers |
| `font_size_body` | 13 | 400 | default, incl. table cells |
| `font_size_caption` | 11 | 400 | helper text, timestamps |

Body is 13px, not the Windows 12px default: these are dense data tables read across a
warehouse desk, and the extra pixel is the cheapest legibility win available.

## 5. Component inventory

Every entry below is justified by an existing defect or an existing duplicate. Nothing here
is speculative — components not on this list are not built in 8.5.

`gui/components/` today holds `card.py` and `form_section.py`. `StatusDot` already exists in
`shared/theme.py` and is reused, not rebuilt.

| component | why it exists |
|---|---|
| `NavRail` | the shell the navigation map depends on; needed by both apps |
| `StatusBadge` | Session Browser's status column is a raw combobox with hardcoded `blue`/`darkgreen`/`red` — named debt in the scope doc, and the direct consumer of §3.4 |
| `ActionBar` | five buttons overflowed the window at the app's own default size (fixed reactively in #291); an overflow-aware bar prevents the next recurrence |
| `StepHeader` | names the open session and how it was opened (built via Setup, or loaded from History); carries Packing's genuine select→pack sequence |
| `EmptyState` | Analysis Results renders blank when opened with no session loaded — the one cold-entry case neither real entry path covers (see navigation map §2) |
| `InlineMessage` | success/warning/danger notices; the second consumer of §3.4 and its tint tokens |

`ColumnConfigPanel`'s list collapse (~70px) is scroll-area starvation identical to
`2026-08-23-session-setup-layout-design.md`. It is a layout bug, not a component — it stays
in 8.6 and is called out here only so 8.5 does not adopt it.

| item | obligation |
|---|---|
| 8.2 | add every token above to `packing-tool/shared/theme.py`, additively; extend `_COLOR_FIELDS` so `validate_theme` covers them; sync into this repo |
| 8.3 | replace all 125 hardcoded hits with these tokens; add the lint rule; migrate `accent_*` call sites to `status_*` |
| 8.4 | unaffected by this spec — structural only, deliberately isolated |
| 8.5 | build §5 and nothing beyond it |
| 8.6 | consume §3–§5; navigation per the companion map |

**Acceptance for 8.2:** a test asserting every colour token in both themes meets the ratio
stated in §3. The tables above are the fixture. This is what stops the light-mode regression
from recurring — the current palette failed silently for as long as it has existed because
nothing measured it.

## 7. Deliberately excluded

- **No rebrand.** Hues are held fixed; only lightness moves. (Q1)
- **No motion/animation tokens.** Nothing in either app animates, and adding tokens for
  transitions nobody has asked for is speculative.
- **No density modes.** One density, tuned for warehouse screens.
- **No icon redesign.** The 19 Lucide icons are fine; 8.4 gives packing-tool the same set.
