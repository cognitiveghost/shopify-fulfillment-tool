# Phase 8.6 — Shell: NavRail + CommandBar

**Status:** design, Stage A.
**Parent contract:** `docs/superpowers/specs/2026-08-26-phase8-unified-design-system.md` §5, §6.
**Depends on:** 8.5 (PR #300 / packing #165, both merged @ `f892ceb`).
**Worktree:** `worktree-phase8-shell`.

---

## 1. What this item does

`NavRail` and `CommandBar` shipped in 8.5 with no call site. 8.6 gives them one: the
Shopify Tool's main window loses its tab bar and its two-row global header, and gains a
56 px rail on the left and a one-row command bar on top.

Roadmap §2 says "both apps". **This cycle covers the Shopify Tool only.** §5 below states
why the Packing Tool is a separate item and what has to be decided before it can start.

## 2. What is on `main` today

`gui/ui_manager.py::create_widgets()` builds a horizontal layout of two things:

- `ClientSidebar` — 70 px client cards, pinned/group sections, and a context menu carrying
  pin / edit / move-to-group / delete plus the create-client and groups dialogs.
- a right-hand column of `_create_global_header()` (two rows: sidebar toggle, client
  label, connection button / folder icon, "Session:", session label, and an `HLine`)
  above `main_tabs`, a five-tab `QTabWidget`.

`main_tabs` has 30 references across `gui/ui_manager.py`, `gui/actions_handler.py`,
`gui/main_window_pyside.py` and `tests/test_session_setup_layout.py`. `client_sidebar`
has 13.

## 3. The three decisions

### 3.1 The tab widget stays; its tab bar is hidden

`NavRail` drives the existing `QTabWidget` through `setCurrentIndex`, and
`main_tabs.tabBar().hide()` removes the tabs from view.

A `QTabWidget` whose tab bar is hidden *is* a `QStackedWidget` with an API this codebase
already speaks. Swapping in a real `QStackedWidget` would rewrite 30 call sites, the five
`Ctrl+N` shortcuts and a test file to produce a screen the user cannot tell apart. The
rail owns the chrome; the tab widget stays the page store.

**The binding is two-way, and that is load-bearing.** `actions_handler.py:256` and
`main_window_pyside.py:1157` jump the user to Analysis Results after a run. With only the
forward edge (`rail.currentChanged → tabs.setCurrentIndex`) those jumps would move the page
and leave the rail highlighting the wrong destination. So:

- `rail.currentChanged` → `main_tabs.setCurrentIndex`
- `main_tabs.currentChanged` → `rail.set_current`

The cycle terminates because both sides already early-return on an unchanged index:
`NavRail.set_current` returns before emitting when `index == self._current`, and
`QTabWidget` does not re-emit `currentChanged` for the index it is already on. No guard
flag is needed, and adding one would hide a real regression if either invariant broke.

**Icons and tooltips move to the rail.** `_TAB_ICONS` keeps its five names and its
position in `tests/test_icons.py`; `_refresh_icons()` sets `rail.button(i).setIcon(...)`
instead of `main_tabs.setTabIcon(...)`. The five `setTabToolTip` calls become
`rail.button(i).setToolTip(...)` with the same text, `Ctrl+N` hint included.

**Labels are verbatim** (spec §6 guardrail 2): `Session Setup`, `Analysis Results`,
`Session Browser`, `Information`, `Tools`. Renames are a later release.

### 3.2 The CommandBar replaces the global header, not the sidebar's job

`_create_global_header()` is deleted. Its contents map onto the `CommandBar`:

| header widget | becomes |
|---|---|
| `current_client_label` ("No client selected") | the client dropdown |
| `session_folder_icon_label` + "Session:" + `session_info_label` | `CommandBar.set_session()` |
| `connection_btn` | a ghost tool button on the bar |
| `sidebar_toggle_btn` | a ghost tool button on the bar |
| the `HLine` separator | the bar's own `border-bottom` |

`CommandBar` as shipped has one trailing widget — the single primary `action_button`. Two
buttons here (and more in 8.7) earn one addition:

```python
def add_tool_button(self, icon_name: str, tooltip: str) -> QToolButton
```

inserted before the stretch. It is a **ghost** role, never primary: "one primary per
screen" stays structurally true because `action_button` remains the only primary.

`self.mw.session_info_label` keeps its name, pointing at the bar's label, so
`update_session_info_label()` (`main_window_pyside.py:692`) needs no edit.
`current_client_label` cannot survive as a name — a `QComboBox` has no `setText` — so
`main_window_pyside.py:838` switches to setting the dropdown's current client id. That
call is already `hasattr`-guarded.

`connection_btn` and `sidebar_toggle_btn` keep their names because `_BUTTON_ICONS` looks
its widgets up by attribute (`ui_manager.py:83-88`) and `tests/test_icons.py` asserts on
that dict.

### 3.3 The client sidebar collapses; nothing is deleted

Spec §5 says the sidebar of 70 px cards becomes a dropdown. The **selector** does — client
*selection* moves to `CommandBar.clientChanged → MainWindow.on_client_changed`, the same
slot `ClientSidebar.client_selected` feeds today, so the downstream is unchanged.

The sidebar also carries pin, edit, move-to-group, delete, create-client and the groups
dialog. A dropdown carries none of those, and deleting them is not a restyle. So the
sidebar stays in the layout, **starts collapsed**, and is reached from the bar's toggle
button. `set_active_client` continues to be called (`main_window_pyside.py:836`) so the
two stay in sync in both directions.

Retiring the sidebar entirely is a later item, once the dropdown has survived contact with
the floor and client management has somewhere else to live. Doing it here would make the
navigation commit unrevertible, which is exactly what guardrail 1 forbids.

## 4. Commit split

Spec §6 guardrail 1: navigation must be revertible on its own.

1. **Chrome.** `CommandBar` in, `_create_global_header()` out, sidebar collapsed by
   default, `add_tool_button` added to the component. No page-switching behaviour changes.
2. **Navigation.** `NavRail` in, tab bar hidden, the two-way binding, icons and tooltips
   moved. Reverting this one commit restores the tab bar and leaves the command bar
   standing.

## 5. Why the Packing Tool is not in this cycle

Two findings from `packing-tool@origin/main`:

- **It has no tab bar to replace.** Its top level is a two-page `QStackedWidget` (session
  view ↔ packer mode) driven by a menu bar and toolbar. Packer mode is deliberately
  full-bleed at floor density. A rail there would hold two items, one of which is entered
  by scanning rather than clicking — worse than the menu bar it would replace.
- **It does have a command bar already, unnamed.** `gui/main_window.py:213-233` is a
  "Client:" label plus a `QComboBox` in a bordered row. That *is* `CommandBar`.

Giving it the real component means moving `NavRail`/`CommandBar` from shopify's
`gui/components/` into `shared/`, which needs the same treatment 8.5 gave the shared
widgets: `theme` becomes an explicit argument, and `icon()` resolution moves to the caller
because `shared/` may import neither app's `gui`. The 8.5 handoff recorded "do not
pre-move" for exactly this reason.

**Open question for the user, ahead of 8.6b:** does the Packing Tool get a NavRail at all,
or only the CommandBar? The recommendation is CommandBar only — there is nothing for a rail
to navigate — but Parcker §09 names app chrome as something the rail replaces, and the
merged spec does not resolve that against the Packing Tool's actual two-view flow.

## 6. Acceptance

A new `tests/test_shell.py` covering, headless:

1. `main_tabs.tabBar().isVisible()` is false and the rail has five items.
2. Rail labels equal the five tab titles verbatim — the guardrail as an executable check.
3. Clicking rail item *n* moves `main_tabs` to *n*.
4. `main_tabs.setCurrentIndex(1)` — the `actions_handler` path — moves the rail to 1.
5. `Ctrl+3` moves both.
6. The command bar carries client, session and status, and the header widgets are gone.
7. `_refresh_icons()` leaves every rail button with a non-null icon after a theme toggle.

Plus the repo gate: `QT_QPA_PLATFORM=offscreen python -m pytest` and
`ruff check . --exclude shared`.

## 7. Out of scope

Restyling the five pages (8.7), the Analysis Results direction (8.8), packing-tool screens
(8.9), removing `ClientSidebar`, renaming any destination, and flipping the global button
default (8.5 handoff: 112 shopify buttons, opt-in until a screen designates a primary).
