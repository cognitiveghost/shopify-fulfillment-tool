# Phase 8.4 — Packing Tool structural migration — Design

**Repo under change:** `packing-tool` (this repo carries only the spec and the plan).
**Roadmap item:** `docs/superpowers/plans/2026-08-26-phase8-roadmap.md` §2, item 8.4.
**Depends on:** nothing. **Blocks:** 8.5 (component library), 8.9 (packing screens).

---

## 1. What this is

Packing Tool ships as a single-file PyInstaller `.exe` built from a flat `src/` directory
whose modules import each other by bare name (`from packer_logic import PackerLogic`),
which only resolves because `src/` is put on `sys.path` in four separate places. Shopify
Tool ships an onedir bundle built from packages (`gui/` + `shopify_tool/`) with a root
entry point, bundled Lucide icons and a bundled Inter face.

This item closes that gap. It is **structural only** — no widget changes colour, moves or
gains an icon. That isolation is the point: 8.4 is the riskiest item in the phase because
the failure mode is *a Windows executable that no longer starts*, and that is only
bisectable if the diff contains nothing cosmetic.

**Non-goals.** No restyling, no new widget, no icon wired into any screen, no `shared/`
edit. `shared/` is authored here and synced into Shopify Tool, so touching it would drag
Shopify Tool into a PR whose whole value is being confined to one repo.

## 2. What is actually there today

Measured on `packing-tool@53c36e4` (the 8.3 merge).

| | |
|---|---|
| `src/` | 26 modules, 11 842 lines, flat except `src/session_browser/` |
| entry | `src/main.py`, run as a script; `if __name__ == "__main__"` at line 2760 |
| `sys.path` edits | 4: `src/main.py:20-23`, `tests/conftest.py:23-24`, `pytest.ini`, `main.spec` `pathex` |
| import sites to rewrite | **47** (41 module-level, 6 function-local) |
| build | `main.spec`, one `EXE`, no `COLLECT` → `dist/Packers-Assistant.exe` |
| assets | none — no icon set, no bundled font; `src/*.qss` was deleted, but `main.spec` still globs for it |

**The GUI/backend boundary already exists and is clean.** Ten modules import no
`QtWidgets` at all, and — verified by grep over every non-stdlib import in those ten —
**not one backend module imports a GUI module**. Nothing has to be untangled; the
directory simply does not express a separation the code already obeys.

| backend (no `QtWidgets`, 10) | GUI (16) |
|---|---|
| `async_state_writer` `exceptions` `json_cache` `packer_logic` `profile_manager` `session_history_manager` `session_lock_manager` `session_manager` `session_registry_manager` `worker_manager` | `main` `packer_mode_widget` `order_table_model` `custom_filter_proxy_model` `restore_session_dialog` `session_selector` `sku_mapping_dialog` `worker_selection_dialog` `theme` + `session_browser/` (7) |

`packer_logic` is a `QObject` with signals, not a widget; it stays backend.

## 3. Target layout

```
main.py                     # entry point: argparse, QApplication, MainWindow
gui/                        # everything Qt-facing
    __init__.py
    main_window.py          # today's src/main.py, minus the __main__ block
    workers.py              # SessionStartWorker, SessionEndWorker
    theme.py  fonts.py  icons.py
    assets/{icons,fonts}/
    session_browser/…       # unchanged, moved wholesale
    …widgets and dialogs
packing_tool/               # everything that is not Qt-facing
    __init__.py
    packer_logic.py  profile_manager.py  session_*.py  json_cache.py …
shared/                     # untouched
tests/
```

Two packages, not one. `gui/` alone would leave backend tests importing
`from gui.packer_logic import PackerLogic` for a module with no UI in it — and the split
costs nothing extra, because §2 shows the boundary is already respected. `packing_tool/`
mirrors Shopify Tool's `shopify_tool/` deliberately: after this item, both repos read the
same way.

**Imports become absolute everywhere** — `from packing_tool.packer_logic import
PackerLogic`, `from gui.theme import current_tokens`. One rule, mechanically greppable, no
per-file judgement about when a relative import is nicer.

**Four `sys.path` edits become zero.** Running `python main.py` from the repo root puts the
root on `sys.path`; `gui`, `packing_tool` and `shared` are then all importable as
siblings. `pytest.ini`'s `pythonpath` drops to `.`, and `conftest.py` loses both
`sys.path.insert` lines. This item deletes the path-hack layer rather than relocating it.

## 4. The build: onefile → onedir

`main.spec` is kept and rewritten, rather than replaced by CLI flags in the workflow the
way Shopify Tool does it. Parity that matters is the **output format**, not the
configuration mechanism, and a version-controlled spec file is reviewable in the PR where
a YAML `run:` block is not.

The rewrite is mostly deletion:

- entry `src/main.py` → `main.py`; `pathex` drops (root is implicit)
- `hiddenimports` drops entirely — every name in it was invisible only because of the flat
  namespace; static analysis finds `gui.*`, `packing_tool.*` and `shared.*` once they are
  real packages
- `datas`: the `src/*.qss` glob goes (those files no longer exist) and `('shared','shared')`
  goes (`shared` is an ordinary imported package, not data); `('gui/assets','gui/assets')`
  is added
- `EXE(…)` splits into `EXE(…, exclude_binaries=True)` + `COLLECT(…, name='Packers-Assistant')`

**This changes what warehouse PCs receive**: a `Packers-Assistant.zip` to extract, not a
single `.exe`. Shopify Tool already distributes this way, so the procedure is not new to
the site, but it is a deployment change and belongs in the release notes.

### 4.1 The build must run on the PR

`build-release.yml`'s build job is `if: github.event_name == 'release'`. As it stands, a
PR that breaks the frozen build passes CI green and the breakage surfaces at the next
release — which for the one item in this phase whose review *is* the Windows build is
exactly backwards.

Add `workflow_dispatch` to the workflow's triggers and widen that condition to
`github.event_name != 'pull_request'`. Stage C then triggers the build against the branch
by hand. One line each; no per-PR Windows-runner cost.

The `sanity-check` job also hardcodes the old layout in two steps (`py_compile src/*.py`,
and an `import main` with `working-directory: src`); both become root-relative.

## 5. Assets

`gui/assets/` receives Shopify Tool's set verbatim: 17 Lucide SVGs + `LICENSE`, and
Inter Regular/Bold + `OFL.txt`. `gui/icons.py` and `gui/fonts.py` are ported from Shopify
Tool with one adaptation — `icons.py` reads the active colour from `gui/theme.py`'s
`current_tokens()` instead of `theme_manager.get_current_theme()`.

Wiring the font in requires a small change in `gui/theme.py`, and it is worth being
precise about why. `shared.theme.apply_theme(app, name)` re-derives its tokens from the
*name*, so a font layered onto a token object cannot reach the global stylesheet through
it. Shopify Tool solves this by not calling it — `theme_manager` composes
`build_stylesheet(tokens)` and `build_palette(tokens)` itself from font-layered tokens.
Packing Tool's `apply_theme` adopts the same shape. **This is a local change in
`gui/theme.py`; `shared/theme.py` is not edited.**

No icon is placed on any widget in this item. The deliverable is the pipeline plus proof
it works — one test that renders a glyph and asserts a non-null pixmap, one that asserts
the Inter family registers. Choosing which glyph belongs on which button is 8.9's work.

> **Deferred, deliberately:** `icons.py` and `fonts.py` will now exist near-identically in
> both repos. They are candidates for `shared/`, which would delete one copy — but that is
> a cross-repo change, and 8.5 already owns the "`gui/components/` vs `shared/`" decision
> per component. Duplicated once, flagged, revisited there. Moving it now would break this
> item's isolation for no benefit 8.4 can measure.

## 6. `src/main.py`'s 2 780 lines

The roadmap says this file "gets a real refactor". This design **splits that off into its
own cycle (8.4b)** and moves the file to `gui/main_window.py` otherwise unchanged, for two
reasons.

1. **It destroys the bisect.** The whole justification for isolating 8.4 from the visual
   items is that a bundle which stops launching must be explicable by a diff containing
   nothing but moves. A behavioural refactor of the main window in the same PR reintroduces
   precisely the noise the isolation exists to prevent.
2. **8.6 rewrites a third of it anyway.** `_init_ui`, `_init_menu_bar`, `_init_toolbar` and
   `_init_status_bar` — 320 lines — are the shell, and 8.6 replaces the shell with NavRail +
   CommandBar. Extracting them now is work done twice.

What 8.4 *does* extract is the one piece with no such overlap: `SessionStartWorker` and
`SessionEndWorker`, two `QThread` subclasses that are not part of the window at all, into
`gui/workers.py` (~80 lines, no `self` shared with `MainWindow`).

The seams for 8.4b, measured, so that cycle starts from evidence rather than a re-read:

| lines | cluster | note |
|---|---|---|
| 177–500 | `__init__` + four `_init_*` shell builders | **8.6 rewrites this — do not extract** |
| 501–887 | order tree + statistics tab | view construction |
| 1335–1870 | `start_shopify_packing_session`, `end_session` | **535 lines; the densest controller logic in the file** |
| 1899–2183 | scan callbacks (`on_scanner_input`, `_on_*`) | controller |
| 2184–2444 | `open_shopify_session`, `enable_packing_mode` | controller |
| 2445–2720 | session-browser handoff + lock-error dialogs | controller |

The natural first extraction for 8.4b is a session-lifecycle controller from rows 3 and 5;
it is the largest cluster, it holds no widget construction, and 8.6 does not touch it.

## 7. Risks

| risk | why it is contained |
|---|---|
| Frozen bundle stops launching | §4.1 makes the Windows build runnable on the PR; it is Stage C's review |
| A missed import site | 47 sites are enumerable and `ruff` resolves module paths; CI's `py_compile` + `import` steps catch the rest |
| A `sys.path` hack elsewhere in the tree | all four known edits are listed in §2 and removed together; `grep -rn "sys.path"` at the end is the check |
| `shared/` drifts | it is not edited; Shopify Tool's CI already fails on drift |
| Deployment change (zip, not exe) | §4; release-notes item, flagged in the PR body |

---

## 8. Acceptance

1. `python main.py --config config.dev.ini` starts the app from the repo root.
2. `python -m pytest` and `ruff check .` pass.
3. `grep -rn "sys.path" src gui packing_tool tests main.py` returns nothing.
4. No file remains under `src/`; `git log --follow` still traces each moved module
   (`git mv`, never delete-and-add).
5. `pyinstaller main.spec` on Windows produces `dist/Packers-Assistant/` containing
   `Packers-Assistant.exe`, `gui/assets/icons/*.svg` and `Inter-Regular.ttf`, and it
   launches.
6. A test renders one Lucide glyph to a non-null pixmap; a test asserts `Inter` registers.
7. No colour, size or layout value changes anywhere in the diff.
